# Agent回答转文本文件 - 技术说明

## 技术架构

**方案 A：单文件 HTML（纯前端）**

所有代码、样式、依赖都内联在 `agent回答转文本文件.html` 一个文件中，双击即可在浏览器打开使用，无需安装任何环境、无需服务器、无需构建步骤。

## 技术栈

| 组件 | 技术 | 用途 |
|------|------|------|
| 核心框架 | 原生 HTML + CSS + JavaScript | 无框架依赖 |
| Markdown 解析 | marked.js (CDN) | 文件上传时解析 MD |
| 文件下载 | file-saver.js (CDN) | 触发浏览器下载 |
| PDF 生成 | html2pdf.js (CDN) | 将预览区转为 PDF |
| DOCX 生成 | docx.js (CDN) | 构建 Word 文档结构 |

## CDN 依赖地址

```html
<script src="https://cdn.jsdelivr.net/npm/marked/marked.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/file-saver@2.0.5/dist/FileSaver.min.js"></script>
```

**注意**：使用工具需要网络连接（用于加载 CDN 库）。离线时工具会降级为纯文本模式，DOCX/PDF 导出不可用。

## 核心模块说明

### 0. 输入路径（两条，2026-08-25 修复换行保真）

- **富文本粘贴**：`sanitizePastedHtml()` 白名单清洗 → `inputOrigin = 'rich'` → `htmlToMarkdown()` 读取
- **纯文本/Markdown（粘贴或上传 .md/.txt）**：`setPlainInput()` 以 `textContent` 存储 → `inputOrigin = 'text'` → `getInputText()` 用 `textContent` 保真读取
- 关键约束：编辑器 CSS 必须保持 `white-space: pre-wrap`，且纯文本路径禁止用 `innerText` 读回（渲染语义会折叠换行与缩进，破坏 Markdown 结构）

### 1. 结构识别器（parseContent 函数）
将原始文本解析为结构化块，识别类型：
- `heading` - 标题（## / 第X阶段 / Step X / 短行）
- `conclusion` - 结论句（含"核心问题/目标/总结"等关键词）
- `keyConcept` - 重点概念（>>开头或含"核心/关键/最重要"）
- `arrowFlow` - 箭头流（预扫描区域检测，连续↓→行+短文本行）
- `list` - 列表（-/*/•/数字.）
- `table` - Markdown 表格（`| col |` + `|---|` 分隔行格式）
- `多行 display 公式` - `\[...\]` / `$$...$$` 跨行时先合并为单段落块再进入行内处理（KaTeX 不跨元素配对定界符）
- `code` - 代码块（```包裹）
- `paragraph` - 普通段落

### 2. 强调标注器（highlightInline 函数）
行内高亮关键词：核心、关键、最重要、重点、注意、不要、错误、失败

### 3. LaTeX 公式保护（renderInlineMarkdown / buildParagraphRuns 函数）
- `renderInlineMarkdown()`：在处理 Markdown 行内语法前，先用 Unicode 私有区占位符（`\uF000`/`\uF001`）暂存 `$$...$$`、`\[...\]`、`\(...\)`、`$...$` 公式，避免公式中的 `*` 被误解析为斜体；处理完后还原为原始文本，由 KaTeX auto-render 在 DOM 渲染后渲染
- `buildParagraphRuns()`（DOCX）：同样暂存 LaTeX 公式，去掉外层分隔符后用 Cambria Math 斜体字体生成 TextRun（docx 不支持原生 LaTeX 渲染）

### 4. 模板渲染器（renderBlocks 函数）
将结构化块渲染为带样式的 HTML：
- 标题：H1深蓝/H2蓝色/H3橙色
- 结论：绿色背景+左侧绿色边框
- 重点概念：橙色背景+左侧橙色边框
- 箭头流：浅蓝背景+居中+箭头高亮
- 表格：`<table>` + 表头背景色 + 斑马纹
- 行内关键词：黄色背景高亮

### 5. 导出模块
- **DOCX**：用 docx.js 构建 Paragraph/Heading/Table，含标题层级、加粗结论、callout、箭头流居中、行内高亮、表格（Table/TableRow/TableCell）、LaTeX 公式（Cambria Math 斜体）
- **PDF**：用 html2pdf.js 渲染预览区为 A4 PDF（含 KaTeX 渲染后的公式）
- **HTML**：导出带内联样式的独立 HTML 文件，引入 KaTeX CDN 并在页面加载后自动渲染公式
- **Markdown**：将结构序列化为标准 MD 语法（表格保留 Markdown table 格式）

## 配置项

工具内的可配置项（在 `agent回答转文本文件.html` 中修改）：

| 配置项 | 位置 | 说明 |
|--------|------|------|
| 高亮关键词列表 | `highlightInline()` 和 `buildParagraphRuns()` | 数组 `['核心','关键','最重要',...]` |
| 结论句关键词 | `isConclusionLine()` | 数组 `['核心问题','目标是',...]` |
| 标题最短长度 | `isTitleLine()` | 当前 3 字 |
| 标题最大长度 | `isTitleLine()` | 当前 25 字 |
| 箭头流扫描范围 | `isInArrowFlowRegion()` | 当前向后扫描 20 行 |
| 预览防抖延迟 | `inputText.addEventListener` | 当前 300ms |
| 页面边距 | DOCX 导出 section properties | 当前 1440 DXA (1英寸) |

## 运行环境要求

- 现代浏览器（Chrome / Edge / Safari / Firefox）
- 网络连接（加载 CDN 库）
- 无需 Node.js / Python / 任何运行时

## 如何修改和迭代

1. 用任何文本编辑器打开 `agent回答转文本文件.html`
2. CSS 样式在 `<style>` 标签内（约第 20-180 行）
3. JavaScript 逻辑在 `<script>` 标签内（约第 190 行起）
4. 修改后保存，刷新浏览器即可看到效果
5. 更新 `相关文件/PROGRESS.md` 和 `相关文件/CHANGELOG.md`
